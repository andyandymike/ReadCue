# 中文 ReadCue 首轮本地对照

> 2026-10-01复查说明：本报告保留历史实验的原统计和当时判断。其中继续补规则、以稳定TTS收益作为训练前提的行动建议已撤回；当前处置见[工作复查](../../docs/WORK_REVIEW_2026-10-01.md)，模型主线见[当前计划](../../docs/PROJECT_PLAN.md)。冻结归档未改。

日期：2026-09-28。**建议继续验证真实需求，暂不据此开训。** 现成专用 TN 模型已经解决大多数设计情境，包括网络赞叹与金额中的数字区别。本轮找到一些可复查的可靠性问题，但尚未证明它们有足够频率、影响或训练价值。

这是我们运行现成系统得到的测量，不是论文成绩，也不是 ReadCue 自训成绩。目前没有 ReadCue 检查点或 HF 权重。

## 实际结果

72 条 assistant 原创句子，三组各24条；尚未人工逐条审核。表中是事先约定的表面格式归一化后整句匹配数，不是发音准确率。

| 系统 | 常规数字/日期/单位 | 语境读法 | 原文保留 | 总匹配 | 本机逐句中位耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原样返回 | 0/24 | 8/24 | 24/24 | 32/72 | <0.01 ms |
| WeTextProcessing 1.2.0 | 24/24 | 15/24 | 20/24 | 59/72 | 4.1 ms |
| 已发布中文 TN 0.6B | 23/24 | 23/24 | 21/24 | 67/72 | 236 ms |
| 通用 Qwen3-0.6B，本轮固定提示 | 0/24 | 8/24 | 19/24 | 27/72 | 518 ms |

严格整句匹配分别为32、0、67、22。WeText 的严格0分主要来自自动转换全角标点等表面格式，因此保留严格结果，同时采用运行前确定的格式归一化分数解释内容。不得将严格0分说成全部读错。

专用 TN 有1例编辑解析失败，保留在72条分母中；其他系统没有运行状态失败，也没有输出截断。全家族通过数分别为8/18、13/18、15/18、5/18；每家族4条相关情境，不能视为独立随机样本。

规则在CPU，神经模型在RTX 2060 6GB / WSL / FP16运行，batch=1。加载耗时分别约4.2、90.2、80.9秒，未混入逐句延迟；推理合计约0.32、17.96、38.07秒。专用模型输出局部编辑，通用模型输出整句，耗时不能解释为同计算量架构优劣。

## 差异是否值得训练

**多数语境问题已有现成解法。** WeText 将弹幕中的 `666` 转成“六百六十六”，将取件码 `1202` 转成“一千二百零二”；专用 TN 在对应样例分别给出“六六六”和逐位读法。仅以“中文网语数字规范化”为卖点，当前差异空间不足。

专用 TN 的5条未匹配应分开看：

| 情况 | 本轮观察 | 判断 |
| --- | --- | --- |
| 编辑锚点不存在，1条 | 原文“负3摄氏度”，生成 `-3->负三`，原文没有 `-3` | 实际接口失败，按作者式解析回退原文；应研究恢复或训练，但1条不能证明普遍需求 |
| 字母数字缩写，1条 | `u1s1` 变成 `u一s一` | 违反本轮缩写保留约定，需真实语境与语音确认影响 |
| 型号保留，3条 | `EOS R50`、`RTX 4060/4070`、`ThinkPad T14` 中数字被逐位展开 | 与本轮策略及该模型卡的型号保留声明不一致；逐位读法本身未必是语音错误 |

通用 Qwen 有56/72条逐字照抄输入，常规组为20/24条；大多未执行数字汉字化，还出现“袋子里装了2公斤大米。”只输出“2公斤”、将 `Thank you` 翻译等现象。固定提示中已说明转换与完整保留要求，但这是零示例、单提示、关闭 thinking 的一次采样。**可据此判断该配置不够可靠，不能据此宣称通用 Qwen 不会 TN，或所有通用 LLM 都不适合。** 本轮没有根据输出重新调提示选最好成绩。

规则对常规 TN 已经全部匹配；专用模型总体更符合本轮语境策略。两者都应继续作为强基线，不能只拿自训模型与本轮较弱的通用提示对照。

## 对自训和 Hugging Face 发布的含义

目前最合理的候选是“可靠、可控制、数据来源清楚的中文朗读规范化小模型”，但这还不是已验证的项目定位。

- 先明确实际用户场景，再收集有来源和使用许可的真实问题句；当前没有这类新语料，也没有已确认的标注成本。
- 人工判断现成方案是否真的读错，接入目标 TTS 试听；型号在文本中保留成功也不证明语音正确。
- 比较简单规则、现成模型及其组合能否处理问题。只有独立真实评估上仍有稳定缺口，才值得用训练解决。
- 若进入训练，使用与发布目的相容的基座和数据，并另建独立留出集。本轮样例若用于设计规则、提示或训练，就属于开发材料。

专用对照的[模型卡](https://huggingface.co/leeoxiang/qwen3-0.6b-zh-tn/blob/97f7860d117f651f9aeba1bc6558eec7c378c958/README.md)标为 CC-BY-NC-4.0，并注明含标贝非商业训练数据。独立训练、提供来源更明确的发布方案可能有实用价值，但当前尚未建立替代训练数据，不据此宣称未来权重可商用。通用基座对照见 [Qwen 模型卡](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/README.md)。

本轮外部 API 与租卡费用均为0，未训练、未上传权重；本机电费未测算。推理时间不能直接换算训练预算，历史越南语预算不适用于这轮中文路线。

## 可复查性与限制

- 72句及有限参考均由 assistant 编写，尚无人类审核，不是现场采集、代表性 benchmark 或盲测；参考未匹配未必是错误。
- 推理只接收 id/text，参考、分组和理由仅离线评分。各系统使用自己的固定接口，是实用系统比较，不是同训练条件消融。
- 模型文件按固定revision与上游哈希核验。初次TN加载因新旧分词器字段不兼容而失败，当时没有模型预测，未计入能力分数。
- 加载修复只在内存映射特殊token字段和RoPE参数，原始模型资产不变。完整词表编号、added-token特殊标志、FIM标记均核对通过；另以3条非pilot探针比较原始底层tokenizer与兼容包装器，编码与两种解码模式全相同，EOS空编辑一致。
- 通用Qwen另作非pilot模板检查：包含固定system的173-token输入在模板直接编码、先展开再编码、底层tokenizer三种路径逐token相同，空thinking后缀及EOS配置一致。未发现明显调用接口错误，但这不替代提示优化或多次采样评估。
- identity早于最终冻结清单时间；规则配置与神经加载代码也有逐步变更。原始时间、旧新代码哈希和原因均保留在[冻结记录](../../eval/zh_reading_pilot_v1/freeze.json)，不把本轮称为不可变预注册。参考、公共提示、评分规则没有根据模型输出调整。
- 评分、分母完整性、格式归一化和编辑解析的7项测试通过；这只验证评测工具的部分行为，不替代人工或语音验收。
