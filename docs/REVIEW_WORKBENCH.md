# 本地审阅页

审阅页接在 `data prepare → 人工审阅 → data export` 之间。它读取固定样本和可编辑标注副本，逐条显示原文、保留的上下文及来源，让审核者填写自己的判断。准备目录有 `ai-suggestions.json` 时可加载独立的 AI 预标注，页面仍不自动批准。

## 启动与续审

在 checkout 中运行；已安装核心包时不必设置 PYTHONPATH：

```powershell
$env:PYTHONPATH = 'src'
python -m readcue data review --prepared 'E:\CodexRuntime\ReadCue\data\bilibili-pipeline-2026-09-29\prepare-02'
```

打开命令打印的地址。服务只监听 `127.0.0.1`，每次启动使用独立的随机路径；默认端口8765，可以用 `--port 0` 自动选择空闲端口。终端需保持运行，Ctrl+C 停止。重新运行命令后打开新地址即可继续。数据无需上传，页面没有外部字体、脚本或分析服务；点击来源链接时才由浏览器打开外部来源。

默认保存到准备目录的 `annotations.jsonl`。要使用另一份标注副本，先完整复制该文件，再通过 `--annotations '副本绝对路径'` 指定。标注及其历史必须保存在仓库外或已忽略的位置，不能覆盖固定材料或原始数据。

## 核对 AI 建议

有预标注时，空白待审记录会显示“AI 建议 · 待你核对”，并预填建议判断、完整读法、类型、分类与理由。核对后确认并保存即可；有分歧可直接改表单。建议待讨论和建议排除同样需要本人确认，不会提前计入进度。

当前 v5/v6 为一次确认流程：当前建议尚未审核的条目，无论以前是否已确认，打开即将建议带入完整读法、判断、类型、分类和备注。核对正确后直接点“确认读法并下一条”，不用另点采用建议。以前保存的内容在“查看此前保存的结果”中保留，确认前文件不变，也可主动改用此前结果。已经确认、修改或暂存过的内容，在该条建议未改变时继续保留，刷新及重启不重新被初始建议覆盖。审阅人继续使用本人的默认姓名，AI 来源另存于建议文件和保存历史中，不冒充人工署名。旧 v1–v4 包继续沿用仅空白待审条目自动预填的逻辑。

建议绑定准备包 manifest、样本 ID 和原文哈希；文件不匹配会报告错误。服务运行期间更新建议文件需要重新启动服务，以免页面内容与保存历史记录的版本不一致。下载标注与 `data export` 仍只读取已保存的人工标注，不把独立建议当成答案。详见[本批建议口径与证据边界](AI_PREANNOTATION.md)。

v5/v6 延续整句候选表示：`J D K` 表示英文字母名逐个读，`tomcat` 表示按单词读；多个文本框为不同完整候选，只保留本人接受的版本。本条说明针对实际句子，不再统一显示无关示例。待讨论也显示可编辑候选，并明确暂不纳入答案；纯表情等排除建议使用“确认排除”按钮。原文下的“查看逐段依据”默认折叠，仅用于查理由，不要求另一轮独立标注。保存后的整句参考使用既有导出流程，仍不能据此声称真实音频发音正确。

## 一条样本的操作

1. 审阅人默认填入当前本机用户，可手动修改，或启动时用 `--reviewer '姓名或代号'` 指定。已有记录优先显示原署名；空署名条目沿用当前会话最近保存的标识。预填不产生审核决定，点击保存才写入。
2. 阅读中间的原始评论。根评论仅供理解；上游丢失了真实直接回复对象，不能用根评论替代完整对话。
3. 选择判断：
   - **原样保留**：精确保留原文，包括空白和换行。程序填入原文参考与“原文保留”分类，保存才生效。
   - **填写读法**：每个文本框填写一种可接受的完整句子，允许添加多种合理读法。选择“常规规范化”或“句内语境读法”。情境分类是普通文本框，可以直接输入“数字品牌名”等自定义名称；下方“常用分类”仅用于快捷填入，选择后仍可修改。切换判断保留自定义分类。
   - **待讨论**：证据不足或存在分歧，必须记录原因；已有完整读法候选仍可查看、编辑并保存，待讨论结果不进入评估参考。
   - **排除**：不适合本轮评估，必须记录原因。
4. 点击 **保存并下一条**，或 Ctrl / ⌘ + Enter。按钮成功保存后才前进。只想暂存时点 **存为待审**；该操作不确认案例，允许读法、审核人等字段未填完。

自定义分类在保存成功后（包括“存为待审”）自动加入本批次的可选列表；重新打开时从已有标注恢复，与常用分类去重合并。仅输入但未保存的名称不会加入，其他窗口保存的分类需刷新后才出现。若某个自定义分类在本批所有记录中都被改掉，它也会从可选列表移除。

需要外部上下文才能确定读法时勾选相应选项并存为待讨论。当前评估的模型输入只有本句文本，不能把这种记录确认为纯文本案例。

左侧支持原文和 ID 搜索、状态筛选；未在输入框中打字时，左右方向键切换当前筛选队列。手动修改后未保存时切换或关闭页面会提醒。“待确认建议”和“本轮已处理”按当前建议的实际审核情况计算；v6 会保留未改变条目的已审核进度，只有改变或无法核实的旧建议重新待确认。进度包含已保存的待讨论与排除，不等于“已批准数量”。确认本条后直接带入下一条的新建议；保存修订后保留历史。

“下载已保存标注”先从本地文件读取最新保存版本，包含所有状态和全部样本，方便带走副本；它不创建评测集。有未保存修改时需先保存再下载，避免遗漏当前编辑。

## 保存与恢复

写入前重新校验准备包、全部 ID 以及不可编辑字段。每次保存检查文件 SHA-256 版本，再原子替换标注文件；旧字节和变更回执保存在标注文件旁的 `annotations.history/<事件目录>/before.jsonl` 与 `change.json`（文件名随自定义标注文件变化）。未能保存会明确显示错误并保留当前表单。保存请求期间锁定编辑区，避免用户继续输入的内容被下一条覆盖。

多个页面同时编辑时，旧版本保存会被拒绝。先把尚未保存的读法、备注复制到临时文件，再刷新页面取得最新记录后重做本条；不要用旧下载文件覆盖新版本。跨进程锁只协调使用本工具的写入，外部编辑器不遵守该锁，因此审阅服务运行时不要同时用编辑器保存同一个文件。

历史快照用于恢复和核对，不应覆盖 `review.jsonl` 或 `manifest.json`。需要恢复时，将选定历史快照复制为一个新的标注文件，再使用 `--annotations` 打开；软件校验它是否仍对应同一批样本。原标注、历史和所有第三方原文均留在仓库外。

v5/v6 用最新已提交历史回执中的已保存七字段标注哈希与该条建议哈希，判断当前建议是否已经审核；兼容原先的整包哈希。旧 v5 包按原字节哈希归档在准备目录 `ai-suggestions.history/<sha256>.json`，读取时校验文件哈希、准备包绑定及每条原文，只有逐条建议完全相同才继承原进度。更新无关条目不清空已完成的审核或草稿；改变的条目、无法核实的旧回执和外部恢复的标注会重新要求核对。未提交或失败回执不算已确认。草稿仍算待审，内容和已保存判断继续保留。轮次状态不添加到人工七字段或模型输入。

v6 的口述候选省略明确的句首“回复 @昵称：”结构，仅朗读正文；原文面板仍展示完整来源文本。正文中的称呼、账号提及和网址不因这条规则删除。具体口径见 [AI 预标注](AI_PREANNOTATION.md)。

## 导出评测材料

全部样本完成确认、待讨论或排除后，使用既有 `data export` 命令形成一个全新导出目录，见[数据流程](DATA_PIPELINE.md#完成审核后导出)。导出仍要求每条决定有审核者，批准记录有完整参考、类型和情境分类；只有批准记录进入 `inputs.jsonl`，参考单独保存到 `cases.jsonl`。

审阅人字段是填写者的声明，不是身份认证。页面通过和保存成功都不能证明参考读法正确、真实听感改善或数据发布许可已经核清。
