# 开源项目检查（2026-09-28）

检查对象是当前中文可行性研究仓库，不是模型发布验收。此前存储迁移的本地修改保留；原始冻结文件、依赖锁文件、案例和已有报告不改写。

## 判断与处理

`src/readcue`、冻结的 `scripts`、`eval`、`reports`、历史 `research` 分工适合当前规模。继续保持核心包零强制运行依赖；暂不加入训练框架、服务端、插件系统或自动模型发布。

| 检查发现 | 本轮处理 |
| --- | --- |
| 复现说明只装模型依赖，未安装核心包；测试还使用了不同解释器 | 补上核心安装并统一环境，优先介绍新 CLI |
| WeText 的归档身份未检查版本和规则选项 | 要求 1.2.0 与协议中的三个 false；增加错值、缺字段回归检查 |
| Python 声明从 3.10 起，原 CI 只有 3.12 | 配置 3.10/3.12 × Windows/Linux；新矩阵结果需远端运行确认 |
| 包缺少项目链接，未检查真正发布物 | 更新 SPDX 许可元数据及项目链接，增加 wheel/sdist 检查与仓库外安装验证 |

| 对贡献者缺少简洁的入口与发布边界 | 增加文档导航、PR 模板、安全说明、源码与 HF 权重发布条件 |
| GitHub 私密漏洞报告未启用 | 通过 REST API 启用并回读确认 |

`--project` 定位 checkout，其他相对参数仍按调用目录解析；文档明确此约定，不改变既有路径语义。

## 发布范围

源码仓库可以作为早期研究项目协作；它不是已经可用的 ReadCue 模型。当前没有自训权重、独立评测结论、确定的中文训练数据或模型许可。HF 模型卡与上传要等这些材料真实存在，不能用开源配置齐全代替研究价值判断。

本轮不更新历史依赖锁文件，不改数据标签，不重跑神经基线，不训练或付费。配置与本地验证记录不能代替新 CI 的实际运行，也不构成模型能力证据。

## 提交后的远端验证

配置提交 `a5e549f` 的[首次四组合 CI](https://github.com/andyandymike/ReadCue/actions/runs/36426828889)中，Python 3.12 的 Windows/Linux 通过；Python 3.10 两个平台均在归档汇总精确比较时失败。原因是 [Python 3.12 改变了浮点数 sum 的算法](https://docs.python.org/3/library/functions.html#sum)，耗时总和末位不同，例如 TN 为 `17.960065127999943` 与历史 `17.96006512799994`。模型输出、匹配数与评分没有差异。

修复将新归档入口的耗时求和明确为 `math.fsum`。四个基线的已有耗时汇总均与该算法完全一致，不改历史报告、不改冻结哈希，也不放宽已有精确比较测试。修复后的四组合结果由 [main 分支 CI](https://github.com/andyandymike/ReadCue/actions/workflows/ci.yml?query=branch%3Amain)核验；保留首次失败记录供追溯。
