# ReadCue 项目计划

更新日期：2026-10-01。用户要求复查近期工作，撤回错误方向并补齐缺项。本计划取代先前以持续补规则及TTS试听为主线的推进方式；旧计划内容保存于[中文探索阶段记录](archive/ZH_EXPLORATION_PLAN_2026-10-01.md)。

## 目标

完成一个可独立下载、运行、评估的小模型研究发布：让模型根据中文句子上下文选择读法，在需要时展开非规范表达，同时保留其余正文。交付模型权重或明确基座版本的adapter、推理示例、数据来源记录和可复现对照。

中文方向沿用用户决定。当前没有ReadCue检查点；现有成绩属于规则或第三方模型。首轮继续使用整句输入、整句规范化文本输出，不同时增加音素、多语言或应用服务。

## 此次撤回与保留

撤回“必须先证明现成方案无法解决、或先证明TTS整体提升，才进入训练讨论”的硬门槛。是否改善是实验要回答的问题；允许完成并报告负面结果。数据适用范围、评测隔离、资源上限和费用授权仍需在实际训练前明确。

撤回把学校编号、表情和英文规则逐条补全作为当前主线的安排。v1至v4保留为探索对照和可复现历史，不作为待不断扩展的产品能力；它们的开发集分数不能代表ReadCue模型学习效果或独立泛化。

保留用户要求的数据清洗、审阅网站、默认审阅人、自填分类、建议预填和版本化确认。保留用户标注、原文、旧预测、音频及精确试听记录。发现标签或实现缺陷时，另存勘误和适用范围，不覆盖旧实验成绩。

本次逐项处置见[近期工作复查](WORK_REVIEW_2026-10-01.md)。历史协议中的下一步建议以本计划为准，历史参数与结果仍按各次冻结材料复现。

## 下一个交付：首轮有界模型实验

具体方案见[模型实验v1](MODEL_EXPERIMENT_V1.md)。研究问题是：在固定中文读法政策下，小模型能否学习需要的转换，并减少对无需转换正文的误改？

| 步骤 | 要交付什么 | 完成条件 |
| --- | --- | --- |
| 任务契约 | 唯一输入输出形式、读法政策、歧义处理 | 训练目标与推理接口一致，不把备注或人工分类当输入 |
| 数据准备 | 来源台账、可用目标、去重与分组划分 | 训练用途已明确；未定标签隔离；开发与评测污染可追溯 |
| 首轮训练 | 固定基座、有限配置、一次有上限的训练记录 | 成功训练并保存检查点、耗时和资源记录；失败只结束尝试，不冒充完成交付，不要求先验必胜 |
| 效果判断 | 原文、固定规则、现成模型、自训模型的同批对照 | 区分整句匹配、局部读法、正文误改和执行失败；独立评测只用于最终判断 |
| 研究发布 | 可加载产物、复现方法、模型卡与局限 | 来源和发布条件明确，能力主张不超过测量；负面结果也可交付 |

TTS只作为少量案例的辅助验证，不再作为上述各步不断前移的门槛。不为提高当前开发集分数继续扩规则。

## 当前缺项及可复用材料

- 已审核138条评论用于开发与回归；其中的使用许可问题尚未由人工确认读法解决，不能自动纳入可发布模型的训练集。已看案例不能重新随机划出所谓盲测。
- 72条原创pilot及其他原创控制可用于接口、开发和工程检查；用途允许且目标复核完成的部分可重新登记为训练或验证材料，无需为了训练全部重造。它们不能再作为未见独立评测，也不能包装成自然评论。
- 现有真实评论来自少数同源视频；首轮正式评测需要独立于规则设计和模型调参的材料，并按来源、近重复和表达家族记录隔离情况。
- 现有Qwen3-0.6B通用基座可作为首轮候选；第三方专用TN继续作外部对照，其权重不是ReadCue权重。
- 本次补齐实验协议、材料审计和勘误，不把这些文档或检查当作训练已完成。数据与运行条件达到协议要求后，进入一次有限实验，不再先开一轮规则优化。

## 证据与资源边界

论文结果、数据/词典审计、第三方基线结果和未来ReadCue模型测量分别报告。现有文本EM不是发音准确率；已确认的音频只支持对应产物。此前查看过的UGTPhon test不称为未见盲测。

首轮优先使用现有本地资源，外部付费预算仍为0；历史200–500美元只是规划。任何后续付费运行须有明确授权与上限。不得为了尽快训练而隐去数据来源、改写参考或泄漏评测标签。

历史数字、逐例结论和复现路径见[文档导航](README.md)。新研究结果不得覆盖历史结果。
