# UGTPhon 实际数据审计（2026-09-28）

## 结论

这次读取并校验了官方英文、越南语全部 train/dev/test 数据，结果让判断更具体：**公开数据基本可用，未发现大规模句子重复；简单词典在已知缩写上很强，但不加判断地用它改写普通词会造成明显错误。** 因此不能说“查表已经够了”，也不能把词典命中的收益全部算作模型推理能力。值得研究的是未知形式、判断是否需要改写及真正歧义的联合能力。

越南语音素标签存在明显表示差异：同一个缩写、同一规范词，在训练与测试中可能使用不同音素字符串。这会影响严格 EM，尚不能认定是错标或断言论文 PER 无效。需要按论文音素分词方式和语言学解释另行核实。

- 官方仓库：https://github.com/naver-ai/UGTPHON
- 固定 commit：`da2b3ee84e15e98ba48b388f7ee291ba4c3579b2`；此次 API 查询 main 仍为该版本。
- 固定树：https://api.github.com/repos/naver-ai/UGTPHON/git/trees/da2b3ee84e15e98ba48b388f7ee291ba4c3579b2?recursive=1
- 仅读取 `en/{train,dev,test}.json` 与 `vi/{train,dev,test}.json`，共 **38,278,189 bytes**。每份内容按 Git blob SHA-1 与固定树核验，另留 SHA-256、URL、字节数于 `manifest.json`。
- 数据位于本目录 `data/en/` 与 `data/vi/`。没有取模型权重、没有克隆仓库、没有训练或付费调用。
- `audit_data.py` 产生 `aggregate.json`；`audit_supplement.py` 产生 `supplement.json`。运行：`python -X utf8 work/ugtphon-deep-audit-20260928/audit_data.py`，然后运行同目录 `audit_supplement.py`。脚本再次运行复用已下载数据，仍校验固定版本内容。
- `audit_filtered_lookup.py` 产生 `filtered-lookup.json`，提供只使用训练标签过滤普通词冲突的更公平查表对照，以及两个可疑词映射的对齐诊断。
- 汇总输出不包含原社媒句子、原始 ID 或用户名。只展示普通词级例子。

## 方法

句子比较使用 Unicode NFC + 连续空白归一化，主结果保留大小写，另报 casefold 敏感性结果。比较的是实际 `text` / `canonical`，**不以 ID 判重**。

词典只从训练集 `is_nc=true` 的 token 建立。键为 NFC+空白归一化的 surface；规范化词典选出现次数最多的 canonical，音素词典独立选出现次数最多的 phoneme，平票按字典序确定。不查看测试标签来挑选答案。主 EM 比较完整归一化字符串；另算逗号音素备选形式相交的宽松值。

**这些是规范化/音素字符串 exact match（EM），不是论文的 Phoneme Error Rate（PER），无法拿 77% EM 与 20% PER 直接比较。** 用测试 `is_nc` 分组只用于统计。另实现不看该标签进行路由的全部 token 查表对照。

## 样本与重复

| 语言 | train | dev | test | 非规范 token（train/dev/test） |
|---|---:|---:|---:|---:|
| 英语 | 3,329 | 600 | 1,100 | 4,106 / 737 / 1,327 |
| 越南语 | 8,597 | 1,129 | 1,121 | 15,836 / 2,112 / 2,152 |

计数与论文/仓库一致。六份数据各自内部原句精确重复均为 0。

英语 train-dev、train-test、dev-test 的原句与规范句，在两种大小写处理方式下交集均为 0。

越南语：

| 对比 | 原句重复 | 原句 casefold 重复 | 规范句重复 | 规范句 casefold 重复 |
|---|---:|---:|---:|---:|
| train–dev | 0 | 1 | 3 | 4 |
| train–test | 0 | 1 | 3 | 4 |
| dev–test | 1 | 1 | 1 | 1 |

表中是不同字符串的交集数；casefold train-dev 规范句4个键对应train6行、dev4行，其他这里的行数与键数一致。dev-test 的原句重复来自 `augmented`。同原句、同标记目标位置未发现跨 split canonical 冲突。

这说明存在少量可清理的重叠，**不支持“大面积训练测试泄漏”结论**。规范句相同也可能来自不同噪声形式，不能自动当成原句泄漏。此次不是语义近重复或同源作者泄漏的完整审计。

## 训练多数词典到底有多强

仅对测试非规范词统计：

| 指标 | 英语 | 越南语 |
|---|---:|---:|
| 训练不同 surface 数（NFC后） | 1,413 | 3,667 |
| 命中测试 token | 941/1,327 = 70.91% | 1,786/2,152 = 82.99% |
| 多数 canonical：命中子集 EM | 914/941 = 97.13% | 1,663/1,786 = 93.11% |
| 多数 canonical：全体 EM，未命中计错 | 68.88% | 77.28% |
| 多数 IPA：命中子集严格 EM | 912/941 = 96.92% | 1,247/1,786 = 69.82% |
| 多数 IPA：全体严格 EM，未命中计错 | 68.73% | 57.95% |

英语音素按逗号备选形式宽松匹配则917个正确，全体69.10%；越南语宽松值不变。规范化宽松备选匹配只让越南语增加1个正确，英语不变。

未做 NFC 的原始 surface 计数为英语1,413键/941命中、越南语3,674键/1,785命中，**准确复现论文的词典覆盖统计**。归一化后的微小差异有可解释来源，不是论文数据规模不实。

### 不依赖 gold 非规范标签路由的现实对照

对 test **所有 token** 执行同一逻辑：训练 NC 词典有键则输出多数 canonical，否则保留原 token。推理完全不读 test `is_nc`，只在评估时按该标签分组。

| 指标 | 英语 | 越南语 |
|---|---:|---:|
| 测试 canonical token 数 | 14,966 | 11,643 |
| canonical token 被改写且不符合 gold | 724（4.84%） | 2,243（19.26%） |
| 从“原样保留本来正确”变成错误 | 200 | 2,243 |
| NC 规范化 EM（miss 保留原词） | 918/1,327 = 69.18% | 1,676/2,152 = 77.88% |

英文 canonical 字段自身大量含大小写、标点或其他规范差异，严格“原样保留 EM”只有10,262/14,966；因此724不能全说成新增错误，严格新增是200。越文原样保留本来11,640/11,643正确，因此2,243基本就是新引入的错误。

敏感性核查：越南语2,243个错误改写，忽略大小写后仍2,243，删除所有Unicode标点后仍2,221（19.08%）。并非主要由大小写/标点造成。但前列映射显示，少数可疑训练配对也在放大这个数：`có→thú` 误改199次、`là→thì`165次、`đi→quảng`141次、`làm→là`82次、`cái→gái`74次、`gì→dì`67次、`còn→càn`64次、`1→một`50次、`nhưng→như`41次、`nữa→nửa`40次。严格规范化错误也不全等于发音错误，例如数字口语化可能对朗读有益。

针对 `có→thú` 与 `đi→quảng`，各自仅来自1条ViLexNorm训练配对。两条行的raw/canonical词数分别6/6和11/11，token列表拼接完整等于对应sentence字段；按SequenceMatcher未找到同surface可保留的邻接位置。因此**未确认是机械邻接错位，也未证明这两个语义配对正确**。完整人工语境与上游标注核验仍未做；不能先把这些异常都算成正常上下文变化。

### 更公平的保守词典：只用 train 过滤普通词冲突

从上述NC词典中，丢弃任何在训练集也以 `is_nc=false` 出现过的surface。推理仍只按surface查表，miss保留原词，不读取测试gold标签。

| 指标 | 英语 | 越南语 |
|---|---:|---:|
| 保留/删除词典键 | 1,279 / 134 | 3,076 / 591 |
| test NC命中token数 | 696 | 888 |
| test NC规范化EM | 703/1,327 = 52.98% | 840/2,152 = 39.03% |
| 原样保留本来正确、被新改错的canonical token | 15/14,966 = 0.10% | 24/11,643 = 0.21% |

**修正推论：19.26%不是模型必要性的证明。** 一个简单训练集过滤规则就能把错误改写大幅降低，但也牺牲许多NC转换。真实问题是覆盖与保留普通词之间的取舍，模型可能改善该取舍，仍需同口径实测。本审计没有证明论文模型已优于这个公平基线。

## 上下文歧义有多少真实证据

训练中一个 surface 对应多个 canonical 的键：英语41、越南语240。测试中同一 surface 在不同句子上下文有多种 canonical：英语10、越南语38；消除 canonical 大小写、外围标点与显式备选形式后为10与35。英语6种、越南语29种在训练与测试两侧都存在多标签。

普通词级的明确例子：

- 英语 `ur`：训练 `your` 33次、`you're` 10次、`you` 1次；测试 `your` 6次、`you're` 4次。两种主要答案确有不同语法功能。
- 越南语 `m`：测试 `mình` 4次、`mày` 27次，存在不同代词展开。`c` 对应 `cậu` / `chị`；`t` 对应 `tôi` / `tao` 也有不同语体的展开。

不能把全部多标签都算成真正语义消歧：比如 `k` 的测试标签含102次 `không` 和1次 `khôgn`，后者至少值得核查拼写/标注；音素变体不等于词义差异。

一个仅用于诊断的测试集 oracle：允许偷看测试分布，为每种 surface 选该测试里最常见 canonical，仍不可避免英语14个、越南语72个严格 EM 错误（分别1.05%、3.35%；越文 canonical casefold 后68个）。这不是可部署成绩，而是说明 **NC 词形→展开内部的消歧只是这个测试的一小部分**。它没有计入“同一 surface 该保留还是改写”的 canonical/NC冲突，也不覆盖未知形式。因此不能由14/72推导上下文总体无用。

## 越南语音素表示差异：查表低分不全是消歧

训练中相同 `(surface, canonical)` 对有多种 IPA 字符串：英语0/1,462对，越南语58/3,979对。越文测试中429个 token 的训练多数 canonical 是正确的，但训练多数 IPA 字符串不匹配：其中270个 gold IPA 在相同训练 `(surface, canonical)` 下见过，159个没见过。

普通词例子：

- `đc → được`：训练 `dɯək˨ˀ˩` 470次，`dɯək̚˨ˀ˩` 24次；测试47次全部是后者。差别包含未释放塞音记号。
- `c → chị`：训练52次 `ci˨ˀ˩ʔ`，测试3次 `tɕi˨ˀ˩ʔ`。这可能涉及转写体系差异，不能仅凭字符串不同认定不同词义。

因此严格 IPA EM 不足以判断模型相对词典的真实语音质量收益。需要统一有依据的转写规则并保留原始评分作对照，不能为了提高分数任意删音素标记。本审计没有生成同口径 PER，也未让人工逐条判定这些变体。

## augmentation 与类别边界

augmentation 分配：英语train111/dev21/test43；越南语228/80/77。原始数据source分别为 LexNorm2015 与 ViLexNorm。聚合文件包含全部类别频数、逐类别和逐source词典覆盖/EM。

公开行只有 source、split 等字段，未提供“由哪个原样本或哪种模板生成”的家族标识。为了有限探查，将每个 NC token 替换成其类别占位符，其他 token 用 canonical 构成句子骨架：英语train-test重合1种、越文2种；这只是一个**粗代理**，短句可能偶然相同，不能称已证明同一生成家族泄漏。英语 augmented test 与其他两split有2种骨架重合，越文3种；完整 canonical 相同的 augmented test 数英语0、越文2。

归纳：augmentation 被分配在所有 split，存在少量重复/相似骨架；缺少生成源/家族ID，所以不能确认按家族完全隔离，也不能仅凭类别相同断言污染。新发布模型应如实说明这项边界。

## 对训练发布价值的影响

1. 数据可实际取得、计数与论文一致，并非只给名义数据链接。
2. 大多数已知 NC 展开可以查表完成，模型不能只用整体 benchmark 分数证明上下文能力。
3. 无标签路由的原始NC词典会误改普通词；只用train过滤后可大幅缓解，但NC准确率随之下降。可下载模型的候选价值是改善这个取舍，加上未知形式与少量真实消歧；19.26%本身不证明模型必要。
4. 越文音素表示需谨慎；以为查表57.95%就“明显差于模型”是不成立的跨指标推论。
5. 这次没有模型推理/训练，故不能证明候选新权重已超过现有论文方法或简单组合系统；能支持的是一项有具体基线、可复核数据的训练研究，而非保证成功的产品立项。
